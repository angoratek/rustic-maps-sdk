# Binding-surface consolidation

Status: audit, complete. Date: 2026-11-04.

## What this gives you

An audit of the four platform binding surfaces against the Rust base and the
frozen UDL contract, with the duplication ranked by value and cost. It answers
three questions:

- Where does a platform surface hand-maintain a fact, a record or a behaviour
  that the UDL generation or the Rust core could own instead?
- For each place, what is the proposed consolidation, does it need a contract
  change, what can it break, and how large is it?
- Which three or four moves remove the most duplication for the least risk?

The contract is `crates/rustic-maps-native-core/src/rustic_maps.udl`, the
public shape is `docs/PublicApiV2.md`, and the provider rules are
`docs/ProviderGenericity.md`. This page records findings only; it does not
open a milestone or change the contract.

## Surfaces audited

| Surface | Generated from the UDL | Hand-maintained | Drift gate |
|---|---|---|---|
| Android | Kotlin bindings through `uniffi-bindgen` | `platform/android/maps-sdk/src/main/kotlin/com/rusticmaps/sdk/` (`MapView.kt` 1,761 lines, `MapsSdkFacade.kt`, `ProviderRegistrationPlan.kt`, Compose entry) | compilation only |
| iOS | Swift bindings through `uniffi-bindgen`; the pod's `MapView.swift` is generated by `scripts/sync-ios-pod-view.mjs` | `platform/ios/Sources/MapNativeCoreUI/` (`MapView.swift` 1,738 lines, `SwiftUIMapView.swift`, location source) | compilation only |
| React Native | ubrn TypeScript/JSI bindings (gitignored, regenerated) | `platform/rn/src/MapsSdk.ts` (1,062), `MapView.tsx` (567), and the native halves (7,757 lines excluding generated output) | type-check only; no record or enum gate |
| WebAssembly | none today: the ubrn web target stays deferred (`docs/PublicApiV2.md` §9) | `crates/rustic-maps-web-bindings/src/` (11,179 lines), `platform/web/types/rustic_maps.d.ts` (752), `platform/web/playground.mjs` (7,097) | `platform/web/tests/contract_sync.mjs` (1,616 lines) |

The three native surfaces consume generated records and enums correctly at
their FFI boundary. The duplication is above that boundary: wrappers, bridge
codecs, the wasm façade and the TypeScript mirrors.

## Findings

### F1 — The contract's `MapView` stops at `draw(camera)`, so every wrapper re-implements the camera value store, fit-bounds, bounds readback and animation

**Status: resolved for the native surfaces (2026-11-17).** The contract now
carries the four `MapView` members and `MapCamera.interpolate`; the Android,
iOS and React Native wrappers hold the contract value as their only camera
state and delegate set, animation, fit and bounds to it. The WebAssembly page
keeps its own camera store until its façade adopts the members.

**Files.**

- `crates/rustic-maps-native-core/src/rustic_maps.udl:2351-2617` (`MapView`
  carries `attach`, `resize`, `set_device_pixel_ratio`, `detach`,
  `set_overlays`, the addressed overlay members, `draw(camera)`,
  `is_frame_settled(camera)`, the location layer, `reload_tile_source` and the
  vector source trio; it has no camera store and no `fit_bounds`).
- `platform/android/maps-sdk/src/main/kotlin/com/rusticmaps/sdk/MapView.kt:214-270,
  379-526, 535-561, 1035-1058, 1184-1200, 1638-1748`.
- `platform/ios/Sources/MapNativeCoreUI/MapView.swift:307-355, 454-590,
  1292-1478`.
- `platform/rn/src/MapView.tsx:72-83, 142-204` (the pose type and handle).
- `platform/web/playground.mjs` owns the page camera state and animation
  (`camera_state`, `camera_preset_eases`, `eased_camera_move_duration_milliseconds`).

**Duplication.** Every surface keeps a camera pose, normalizes it through a
new `MapCamera`, stores the last adopted pose, computes a fitted camera, reads
the viewport's geographic bounds, and runs an animation timeline with a
smoothstep ease and shortest-arc bearing interpolation. The Android and iOS
implementations are structurally the same and their constants match value for
value (60° field of view, 24 maximum zoom, 300 ms animation, 2048-pixel drawable
cap, 1 s watchdog, 3-frame backoff). The wasm page implements the same camera
store and easing a third time. `docs/PublicApiV2.md` §10 already assigns the
camera value store, the overlay bookkeeping and readiness to the SDK; today
only the wrappers own them.

**Proposed consolidation.** Add to the UDL `MapView`:

```text
MapCamera camera();
[Throws=SdkError] void set_camera(MapCamera camera);
[Throws=SdkError] MapCamera fit_bounds(BoundingBox bounds, EdgeInsets insets, double maximum_zoom_level);
BoundingBox? camera_geographic_bounds();
```

and add a pure interpolator to `MapCamera` for the animation step:

```text
MapCamera interpolate(MapCamera from, MapCamera to, double fraction);
```

The wrapper keeps the platform frame clock and calls `interpolate` once per
tick; Rust owns normalization, the fitted pose, the bounds readback and the
shortest-arc bearing math. `camera_geographic_bounds` reuses the existing
corner-unprojection and Mercator fallback from the wrappers' current
implementation, so the answer does not change.

**Contract change.** Yes, addition-only.

**Risk.** The wrapper's public camera API changes shape, and the RN handle and
wasm class must adopt the members in the same round. The camera store moving
behind the view changes when a refused pose is reported (construction-time
instead of the next draw). Mitigate with an adapter round: keep the wrapper
methods, delegate to the contract, and deprecate nothing until the wasm class
has the members.

**Size.** Large.

### F2 — Id-addressed overlay bookkeeping is implemented in Rust and again in every wrapper

**Files.**

- `crates/rustic-maps-native-core/src/surface_view.rs:152-196, 250-270,
  2520-2705` (the identifier sequence, the addressed set, replacement and the
  `set_overlays` reset).
- `crates/rustic-maps-web-bindings/src/canvas.rs:2013-2017, 3361-3502` (the
  same bookkeeping for the canvas).
- `platform/android/maps-sdk/src/main/kotlin/com/rusticmaps/sdk/MapView.kt:276-278,
  563-604, 1222-1240` (a `LinkedHashMap` of caller ids, replaced wholesale
  through `setOverlays`).
- `platform/ios/Sources/MapNativeCoreUI/MapView.swift:386-391, 631-676,
  1480-1497` (a dictionary plus an order array, replaced wholesale through
  `setOverlays`).
- `platform/rn/src/MapView.tsx:161-170` (the caller-id handle).

**Duplication.** Order, replacement, removal, the reset-on-`set_overlays` rule
and the monotonic identifier sequence exist four times. The contract already
owns them in `add_overlay` (which returns the generated identifier),
`update_overlay` and `remove_overlay`; the wrappers use only `set_overlays` and
maintain their own maps, so a caller identifier and a contract identifier mean
different things on the same view.

**Proposed consolidation.** Have the Kotlin and Swift wrappers call the
contract's addressed members and return the generated identifier, exactly as
the wasm `MapView` already does. Where an application must keep a stable
caller-chosen key, let it keep that map in its own code; the SDK should not.
Factor the Rust bookkeeping out of `surface_view.rs` into one shared type and
have the canvas use it, so the identifier format and reset rules exist once.

**Contract change.** No: the members are on the contract. The wrapper API
changes (the RN `addOverlay` identifier becomes the SDK's, not the caller's).

**Risk.** The reference applications and the RN app shell pass their own ids
today; they need one migration pass. `set_overlays` stays the bulk call and
keeps its documented reset semantics.

**Size.** Medium.

### F3 — The React Native bridge hand-mirrors contract records and enum ordinals, and the mirror has already drifted

**Files.**

- `platform/rn/src/MapsSdk.ts:58-352`: hand-written `ProviderCredentialResult`,
  `SdkRegistrationResult`, `DevicePositionFix`, `PositionSourceFailureReason`,
  `UrlTemplateRasterImageFormat`, `UrlTemplateTileResolution`,
  `UrlTemplateRasterTileSourceDefinition`, `UrlTemplateVectorTileSource`,
  `VectorTileSourceStatus`, `RegionImageFormat`, `RegionTileResolution`,
  `RegionDownloadPhase`, `RegionDefinition`, `RegionRecord`,
  `RegionDownloadProgress`, `RegionRemovalReport`. Most of these are UDL
  dictionaries or enums the generated module already declares. The curated
  names stay distinct from the contract's (`PositionSourceError`,
  `UrlTemplateRasterTileSource`) so one import is never ambiguous.
- `platform/rn/src/MapView.tsx:72-83`: a second `MapCamera` pose type beside the
  Android `MapCameraPose` and the iOS `MapCameraPose`.
- `platform/rn/android/src/main/java/com/mapssdkrn/MapsSdkNativeJson.kt` (618
  lines) and `platform/rn/ios/MapsSdkNativeJson.swift` (741 lines): two
  hand-written JSON codecs for the same records, each with its own enum
  ordinal switch.

**Duplication.** Field names, nullable rules, `u64`/`bigint` conversion and
enum ordinals are declared in the UDL, in the generated bindings, in the
TypeScript mirror and again in each native codec. The ordinal coupling is the
dangerous part: the wire contract is the UDL variant order, but nothing checks
it. The audit found one live drift: the iOS decoder's `MapOverlayKind` switch
accepted ordinals 0–3 and rejected the contract's fifth variant,
`PointPins` (ordinal 4), while the generated TypeScript enum and the Android
decoder accept it. A JavaScript caller could add a point-pin overlay on Android
and get `false` with no overlay on iOS. The one-line fix is recorded under
"Small drift found and fixed".

**Proposed consolidation.** In order of increasing scope:

1. Generate the curated TypeScript declarations from the UDL. The contract
   parser already exists inside `contract_sync.mjs`; promote it to
   `scripts/generate-web-facade.mjs` and add a `--check` mode, then generate a
   shared `platform/rn/src/generated/curated_records.ts` (or emit the record
   shapes into the existing generated module) and re-export them from
   `MapsSdk.ts`.
2. Generate the enum ordinal tables for both native codecs from the UDL (a
   small JSON table committed beside the codecs, or code generated by the same
   script), or replace the numeric wire form with the generated record types
   where the React Native bridge allows it.
3. Add a round-trip gate: every `MapOverlayKind`, `LocationIndicatorVisualKind`,
   `RasterImageFormat`, `RasterTileResolution`, `TransportationMode`,
   `RouteStrategy`, `UnitSystem`, `ProviderContract` and
   `RegionDownloadPhase` value crosses the JS surface and comes back unchanged.

**Contract change.** No for generation. Adopting generated record names at the
JavaScript API (for example `bigint` TTLs) is a JavaScript API change, not a
UDL change.

**Risk.** `bigint` is awkward at the JSON boundary; the native module plumbing
(module registration, event emitters, the package-owned `MapSdk`) stays
hand-written by necessity. Keep the JSON wire shape stable in the first round
and generate only the tables and declarations.

**Size.** Large.

### F4 — The wasm surface is a parallel implementation of the contract with a hand-maintained TypeScript mirror

**Files.**

- `crates/rustic-maps-web-bindings/src/exports.rs` (1,150 lines, 50 field-name
  constants, 26 exports), `canvas.rs` (5,157, 86 constants), `navigation.rs`
  (1,209, 43 constants), `live_providers.rs` (1,573), `diagnostics.rs` (504),
  `positioning.rs` (187), `vector_layer.rs` (358), `refapp.rs` (484).
- `platform/web/types/rustic_maps.d.ts` (752 lines, 37 exported types).
- `platform/web/tests/contract_sync.mjs` (1,616 lines) is the only thing keeping
  the mirror aligned.

**Duplication.** The wasm seam re-declares the contract's classes and records:

- `MapCamera` (`exports.rs`), `MapsSdk` (`exports.rs`), `RouteSimulator`
  (`exports.rs`), `Navigator` (`navigation.rs`), `PositionController`
  (`positioning.rs`) as `wasm_bindgen` classes with flattened scalar arguments
  and plain-object results, beside the UDL interfaces of the same names.
- The record shapes in `types/rustic_maps.d.ts`, including renamed projections
  (`NavigatorTripState`, `PlaceRow`, `TrafficFlowRow`) and enum mirrors
  (`CanvasTileResolution`, `CanvasTrafficFlowCongestionLevel`,
  `CanvasSdkLogSeverity`).
- Sixteen error-code string constants in `exports.rs` beside the `SdkError`
  variant names in the UDL and the `SdkErrorCode` union in the TypeScript
  mirror.
- `renderFrame` returns `requestedTiles` / `drawnTiles` / `missingTiles` /
  `drawnFragments` / `overlayTriangles`, while the UDL `FrameStatistics`
  (and every native surface) uses `requested_tile_count` /
  `present_tile_count` / `fallback_tile_count` / `deferred_tile_count` /
  `unavailable_tile_count` / `overlay_triangle_count`. The two shapes are not
  a field rename: `drawnTiles` merges present and fallback tiles, and
  `missingTiles` has no exact counterpart.

**Proposed consolidation.** Promote the UDL parser into
`scripts/generate-web-facade.mjs` and generate `types/rustic_maps.d.ts`, the
error-code union and the enum mirrors; make `contract_sync.mjs` assert the
generated file byte for byte instead of re-parsing both sides. Align the wasm
frame statistics with the contract's fields (keeping aliases for one release),
or generate one adapter that maps the renderer's counters onto the contract
record. Adopt the ubrn web target when it lands (`docs/PublicApiV2.md` §9) so
the class surface itself is generated; until then the canvas shim remains
hand-written because a DOM canvas is not expressible in UniFFI.

**Contract change.** No. Aligning the statistics names changes the wasm API
only.

**Risk.** The page and the Playwright suite read the old statistics names;
ship aliases first. A generated file changes the review surface: the gate must
fail on drift, not on formatting.

**Size.** Medium.

**Implemented (2026-11-04).** `scripts/generate-web-facade.mjs` generates
`platform/web/types/rustic_maps.d.ts` (the mirrored records, enum unions,
the structured `SdkError` union and the `SdkErrorCode` union) and
`crates/rustic-maps-web-bindings/src/generated_contract_field_names.rs` (the
JavaScript field names the wasm exports read and write).
`platform/web/tests/contract_sync.mjs` runs the generator's `--check` mode, so
a one-line drift fails before the callable surface is compared. The canvas
class and the WebAssembly-only projections the UDL cannot express stay
hand-written in `platform/web/types/rustic_maps_surface.d.ts`; the generator
appends that file verbatim.

**Follow-up.** The wasm frame statistics still use the renderer's own field
names (`requestedTiles`, `drawnTiles`, `missingTiles`, `drawnFragments`,
`overlayTriangles`) and do not mirror the contract's `FrameStatistics`;
aligning them changes the wasm API and needs a release with aliases. The class
surface (the canvas `MapView`, `MapSdk`, `MapCamera`, `Navigator`,
`RouteSimulator` and `PositionController`) remains hand-written until the ubrn
web target lands. Wasm-only projection field names (the frame-statistics keys,
the canvas descriptor aliases `positions`/`color`/`segments`/`radiusPixels`,
the navigation event bridge and the positioning record) stay hand-written
because the contract has no counterpart. The five seam-only error codes stay
Rust constants beside the generated `SdkErrorCode` union; deriving them from
one Rust enum with a single `as_str` (F9) is a follow-up. The React Native
curated records and the two native JSON codecs (F3) are outside this change.

### F5 — SDK-owned constants are re-declared in every wrapper

**Files and values.**

| Value | Rust source | Android | iOS | React Native |
|---|---|---|---|---|
| field of view 60° | `crates/rustic-maps-rendering/src/camera.rs:20` | `MapView.kt:1647` | `MapView.swift:256` | pod copy |
| maximum zoom 24 | `camera.rs:28` | `MapView.kt:1684` | `MapView.swift:286` | `MapView.tsx:287` |
| drawable cap 2048 | adapter limit | `MapView.kt:1655` | `MapView.swift:248` | pod copy |
| animation 300 ms | reference UX token | `MapView.kt:1674` | `MapView.swift:283` | `MapView.tsx:284` |
| watchdog 1 s | wrapper policy | `MapView.kt:1664` | `MapView.swift:274` | pod copy |
| unavailable backoff 3 | wrapper policy | `MapView.kt:1672` | `MapView.swift:279` | pod copy |
| double-tap step 1.0 | reference UX token | `MapView.kt:1677` | `MapView.swift:270` | — |

| overlay id prefix `overlay-` | `native-core/src/surface_view.rs:152` | — | — | — |

**Duplication.** Values owned by Rust or by the reference design language are
copied into three or four wrappers, where a change is a multi-platform edit
that no gate covers.

**Proposed consolidation.** Expose the SDK-owned values through the contract
(for example `MapCamera.default_field_of_view_degrees()` and
`MapCamera.maximum_zoom_level()`, or one `MapViewDefaults` record) and have the
wrappers read them. Reference-application timing values (animation duration,
double-tap step, gesture settle delay) belong in
`platform/reference-tokens.json`, which already carries the compass re-north
duration and is enforced by `scripts/check_ux_parity.mjs`; the SDK default for
`animateCamera` should either be that token or a required argument. Wrapper
pump policy (watchdog, backoff) can stay native but should be documented as
wrapper policy and tested once per platform.

**Contract change.** Yes, small addition-only members for the SDK-owned values.

**Risk.** Low: read-only values. The token move can break a refapp build if a
platform mirror is not updated in the same round.

**Size.** Small to medium.

### F6 — Composed navigation text is computed in Rust but not exposed to the native surfaces

**Files.**

- `crates/rustic-maps-navigation/src/instruction.rs:211-222`
  (`DistancePhrase::display_text`).
- `crates/rustic-maps-web-bindings/src/navigation.rs:226-236` uses it for the
  browser turn card.
- `crates/rustic-maps-native-core/src/rustic_maps.udl:2029-2041`: the contract
  carries `DistancePhrase` as kind, magnitude and unit, not text.
- `platform/android/reference-application/src/main/kotlin/com/rusticmaps/sdk/referenceapplication/ReferenceApplicationScreen.kt:2942-2952`,
  `platform/ios/reference-application/Sources/TripPhraseFormatting.swift:23`,
  and `platform/rn/app-shell/ios/MapsSdkRefappRn/RefappDemoSession.swift:1861`
  each reformat the record into "Now" / "130 meters" / "1.5 kilometers".

**Duplication.** The phrase wording lives in Rust and again in three reference
shells. The shells receive the rounded magnitude and unit, so they do not own
the rounding, but every wording change is a four-file edit. The wasm surface
already receives the composed string, so the native and browser experiences can
diverge without any test noticing.

**Proposed consolidation.** Add `string display_text` to the UDL
`DistancePhrase` dictionary (populated from the existing
`DistancePhrase::display_text`) and have the three shells render it. The
structured kind/magnitude/unit fields stay for callers that need them.

**Contract change.** Yes, addition-only.

**Risk.** The wording is consumer-facing; the Rust test suite owns the
boundaries, and the refapp copy tests need one update. Low.

**Size.** Small.

### F7 — The React Native reference shell re-implements Web-Mercator viewport bounds in TypeScript

**Files.**

- `platform/rn/app-shell/src/mapLayersPanelState.ts:408-490`
  (`geographicBoundsForCamera`, with its own Mercator world-size, y-flip and
  inverse projections).
- `platform/android/maps-sdk/src/main/kotlin/com/rusticmaps/sdk/MapView.kt:468-526`
  and `platform/ios/Sources/MapNativeCoreUI/MapView.swift:532-590` already
  expose the same readback to their shells.

**Duplication.** The RN `MapViewHandle` does not expose
`cameraGeographicBounds`, so the shell re-derives the box from the camera pose
and the viewport in JavaScript — a fourth implementation of projection math
that `rustic-maps-rendering` owns.

**Proposed consolidation.** Add `cameraGeographicBounds()` to the RN handle
(the native wrappers have it), and delete the TypeScript math. When F1 lands,
both native wrappers and the handle can delegate to the contract's member.

**Contract change.** No.

**Risk.** Low; the existing TypeScript tests become the parity oracle and
should move to the handle test.

**Size.** Small.

### F8 — The React Native pod ships a generated copy of the iOS `MapView`

**Files.**

- `platform/ios/Sources/MapNativeCoreUI/MapView.swift` (1,738 lines) is the
  source.
- `platform/rn/ios/MapsSdkRusticMapView.swift` (1,742 lines) is generated by
  `scripts/sync-ios-pod-view.mjs` and asserted byte for byte by
  `verifyPodViewMirror()` in the Playwright global setup.

**Assessment.** This is a managed duplicate, not drift: the generator applies a
declared rename map and refuses any difference. It is the model the rest of
this audit recommends for the TypeScript mirrors. The cost is a doubled compile
surface and a second file in every wrapper change.

**Proposed consolidation (optional).** Let the pod depend on the SwiftPM
package through a shared source target and delete the copy. The blocker is a
name collision: the pod cannot import `RusticMapsSDK` because the generated
binding already declares `MapView`. A module rename or a typealias would unblock
it.

**Contract change.** No.

**Risk.** Medium (packaging and module layout).

**Size.** Small to decide; medium to implement.

### F9 — Error codes and validation helpers are duplicated in Rust and TypeScript

**Files.**

- `crates/rustic-maps-web-bindings/src/exports.rs:57-106` (16
  `ERROR_CODE_*` string constants) and
  `platform/web/types/rustic_maps.d.ts:356-378` (`SdkErrorCode` union) against
  the UDL `SdkError` variants.
- `crates/rustic-maps-web-bindings/src/shared.rs:51-95` against
  `crates/rustic-maps-native-core/src/projection.rs:12-45` (the same three
  coordinate, box and viewport validation wrappers).

**Duplication.** The contract variant names are restated in Rust and in the
TypeScript union; `contract_sync` checks them, so this is policed rather than
generated. The validation wrappers are three-line error-message adapters with
two copies.

**Proposed consolidation.** Generate the TypeScript code union from the UDL and
derive the seam-only codes from one Rust enum with a single `as_str`, as part
of F4's generator. Move the validation wrappers into `geospatial-types` or a
small shared helper so native-core and the wasm seam call one function.

**Contract change.** No.

**Risk.** Low.

**Size.** Small.

## Small drift found and fixed

The audit found one live consequence of F3: the React Native iOS bridge's
`MapOverlayKind` ordinal switch in
`platform/rn/ios/MapsSdkNativeJson.swift` accepted ordinals 0–3 and returned
`nil` for ordinal 4, the contract's `PointPins`. The generated TypeScript enum
and the Android decoder both accept it, so the same JavaScript call drew
endpoint pins on Android and resolved `false` without drawing on iOS.

The fix adds `case 4: kind = .pointPins`. It was verified by type-checking the
five pod Swift sources against Swift bindings freshly generated from the UDL
(`swiftc -typecheck`, exit 0). No other ordinal map was missing a variant:
`LocationIndicatorVisualKind` (2), `RasterImageFormat` (2),
`RasterTileResolution` (2), `TransportationMode` (3), `RouteStrategy` (2),
`UnitSystem` (2), `TrafficFlowCongestionLevel` (4) and `ProviderContract` (10)
all cover their contract enums.

A second, cosmetic drift: `platform/web/types/rustic_maps.d.ts` carries the
`MapOverlay` documentation comment immediately above
`UrlTemplateVectorTileSource`, with the real `MapOverlay` interface declared
further down. It is left unchanged because it is documentation-only; the
generator in F4 removes the class of defect.

## Surface corrections after the audit

- The Android AAR now exposes `ProviderCredentialDescriptor` and its
  `VectorStyleDescriptor` member from `com.rusticmaps.sdk`; both lived in
  `com.rusticmaps.sdk.demo` when this audit was written. The descriptor shape is
  part of the shipped wrapper, not reference-application code.
- `CollectingNavigationStateListener` left the AAR. It is reference-application
  code under `com.rusticmaps.sdk.navigation`, so a consumer that needs a
  listener implements the shipped `MapViewListener` contract instead of
  inheriting a demo collector.
- The React Native curated types `PositionSourceFailureReason` and
  `UrlTemplateRasterTileSourceDefinition` were renamed from `PositionSourceError`
  and `UrlTemplateRasterTileSource`. The curated names are deliberately distinct
  from the generated contract records of the same concept, so an import is never
  ambiguous.

## Deliberately not consolidated

- **The frame pump.** `docs/PublicApiV2.md` §10 rules it platform-owned: only
  the wrapper observes window attachment, visibility and pause, and moving the
  loop into Rust needs a foreign callback and a threading story. F1 moves the
  camera *value* and the animation *math* behind the contract; the clock stays
  native.
- **The platform view and surface lifetime.** `ANativeWindow*`, `CAMetalLayer`,
  `UIView` and the JavaScript canvas are platform types by definition.
- **Operating-system location adapters.** Each shell owns its permission
  prompt and location API and pushes fixes into the contract's
  `PositionController`.
- **Provider registration dispatch arms.** `docs/ProviderGenericity.md` allows
  one vendor-named arm per platform; the registry descriptor owns the data.
- **The vendor-neutral transport plumbing.** The provider layer and
  `everymap-core` already own it; the wasm seam reuses the same registry.

## Ranked plan

Ranks are value per unit of risk, not implementation order.

1. **Generate the mirrors from the UDL (F4, F9, and the declaration half of
   F3).** Medium size, no contract change. One generator
   (`scripts/generate-web-facade.mjs`, promoted from the parser already in
   `contract_sync.mjs`) emits the wasm TypeScript mirror, the error-code union
   and the curated React Native record declarations; `--check` fails on drift.
   This removes 752 hand-maintained TypeScript lines and most of the 1,616-line
   gate's reason to exist, and it retires the drift class that produced the
   `PointPins` bug.
2. **Move the camera value store, fit-bounds and bounds readback into the
   contract's `MapView` (F1).** Large, addition-only. It removes the largest
   wrapper duplication (camera store, normalization, fitted pose, bounds
   fallback, animation interpolation across Android, iOS, RN and the wasm page)
   and it is the prerequisite for the RN bounds handle in F7. Keep the frame
   pump native.
3. **Put the React Native bridge's records and enum tables on generated code
   (F3).** Large, no contract change for the first round. It removes the two
   hand-written codecs' ordinal switches and the duplicated record interfaces,
   and it adds the round-trip gate that would have caught `PointPins`.
4. **Adopt the contract's id-addressed overlays everywhere (F2).** Medium, no
   contract change. Delete the Kotlin and Swift overlay maps and share the
   identifier bookkeeping between the native surface view and the canvas; the
   wasm class already follows the contract shape.

**Immediate small wins, independent of the plan above:** expose
`DistancePhrase.display_text` (F6), add the RN bounds handle (F7), and move the
SDK-owned constants (F5) behind contract getters or reference tokens.

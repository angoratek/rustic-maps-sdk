# Architecture

Rustic Maps SDK renders maps on the GPU, resolves places, plans routes, follows a
turn-by-turn trip from simulated location updates, and routes offline from an
OpenStreetMap graph. One Rust core serves Android (Kotlin), iOS (Swift/SwiftUI), React
Native and WebAssembly behind one frozen UniFFI contract,
`crates/rustic-maps-native-core/src/rustic_maps.udl`. `MapView` is the entry point on
every target; the renderer is an own minimal `wgpu` renderer, raster first, with vector
styling drawn onto the same overlay pipeline.

## 1. What the SDK is

Kotlin, Swift and the React Native Turbo Module are generated from `rustic_maps.udl`;
the browser module is generated by the `wasm2` bindgen with a hand-written canvas class
beside it, and `platform/web/tests/contract_sync.mjs` keeps the contract split honest. A
DOM `HTMLCanvasElement` and a `GPUDevice` are not expressible in UniFFI types, so the
canvas adapter is the only hand-maintained piece of the wasm surface.

Dependency direction runs from records to orchestration to consumers: `geospatial-types`
is the record and math layer, `geospatial-traits` adds the ten contracts, and
`rustic-maps-core` names no provider crate. The two binding crates alone construct
vendors and export a contract; on wasm, `rustic-maps-native-core` consumes
`rustic-maps-web-bindings`, so one module carries the contract surface and the canvas
with one initialization and one registry. The offline compiler is a test-only fixture
producer outside the production graph.

## 3. The contract

### One UDL, four consumers

`crates/rustic-maps-native-core/src/rustic_maps.udl` is the single source of the public
API, in the `rustic_maps` namespace and pinned to `uniffi 0.31.2`.
`crates/rustic-maps-native-core/src/rustic_maps_wasm.udl` is that contract minus the
native surface `MapView` interface and its documentation block; both the wasm
scaffolding and the bindgen consume that one file.

| Target | Generated from | Shipped as |
|---|---|---|
| Kotlin | `rustic_maps.udl` through UniFFI | Bindings AAR plus the Kotlin `MapView` wrapper AAR |
| Swift | `rustic_maps.udl` through UniFFI | `RusticMapsSDK` and `MapNativeCoreUI` in the XCFramework and Swift package |
| React Native | `rustic_maps.udl` through `uniffi-bindgen-react-native` | TurboModule package and typed `<MapView>` |
| WebAssembly | `rustic_maps_wasm.udl` through `wasm2`, plus the hand-written canvas adapter | The browser npm package |

Everything except the canvas — record shapes, enum spellings, method and class names,
error variants — is generated, so the browser writes the same camelCase names as Kotlin,
Swift and React Native. The canvas class is exported as `BrowserMapView` so the contract
`MapView`, which the wasm contract strips, never reaches the page; `MapCamera` and the
gesture pose algebra stay beside it, and contract records never cross into the canvas.
The wasm entry keeps `MapsSdk.create()` while the contract interface is the constructor
`MapSdk()`; `contract_sync.mjs` records that tolerance.

### Addition-only changes

The contract is addition-only by default. A breaking change before 1.0 requires an
explicit, recorded product decision and ships with regenerated bindings, reference
applications and documentation in the same commit; the revision that renamed types and
members and introduced the `rustic_maps` namespace is the standing example.
`contract_sync.mjs` is addition-tolerant: it asserts the wasm TypeScript mirror against
the UDL rather than pinning a checksum. Generated bindings are build artifacts; after a
UDL change, run `scripts/build-android.sh` and `scripts/build-ios.sh`, and
`scripts/build-rn.sh` when its surface matters.

### UniFFI constraints

- Per-member `[Async, Throws=SdkError, Name=...]` only; interface-level `[Async]` is rejected by the UDL parser.
- `[Trait, WithForeign]`: the UDL placeholder traits are discarded by the macro path, so the binding crate defines the real Rust traits itself, with matching signatures, `Send + Sync` supertraits and a `#[doc(hidden)] uniffi_foreign_handle` default; `async-trait` is a direct binding-crate dependency.
- Orphan rule: FFI records are crate-local mirrors with explicit converters; E0210 forbids implementing FFI traits for foreign-crate types.
- ubrn renders module identifiers verbatim from the namespace, so it must be `rustic_maps`; hyphens produce invalid TypeScript. It resolves the crate through `cargo metadata` walking up from the current directory.
- On the 0.31.2 line the generated TypeScript's 108 checksum items agree with the Rust scaffolding.

Exported `[Async]` methods hand reactor-dependent work (reqwest, `tokio::time`) through
the crate-owned runtime in `crates/rustic-maps-native-core/src/runtime.rs` using the
`drive()` handback; foreign event loops otherwise panic with "there is no reactor
running". Locks stay short and never span an await, so every exported future stays
`Send`.

### Naming rules

- **R1 — Noun-first types.** `MapView`, `MapCamera`, `MapStyle`, `SearchEngine`, `RoutingEngine`, `Navigator`, `OfflineManager`; never `MapViewHost`, `MapSurfaceHost`, `CanvasManager`.
- **R2 — One concept, one word.** *view*, *camera*, *marker*, *polyline*, *polygon*, *route*, *navigation*, *navigator*, *region*, *provider*, *credential*, *listener*; never *surface*, *scene*, *puck*, *trip*, *subscription*.
- **R3 — Engine = noun + verb methods.** `SearchEngine.search`, `RoutingEngine.calculateRoute`, `Navigator.startNavigation`, `OfflineManager.downloadRegion`.
- **R4 — Approved verbs.** `search`, `suggest`, `reverseGeocode`, `calculateRoute`, `calculateDistanceMatrix`, `startNavigation`, `stopNavigation`, `updateLocation`, `setCamera`, `animateCamera`, `fitBounds`, `panByScreenPixels`, `zoomByLevels`, `rotateByDegrees`, `addOverlay`, `removeOverlay`, `clearOverlays`, `configureProviderSet`, `configureProvider`, `providerRegistrations`, `register`, `downloadRegion`, `deleteRegion`, `addListener`, `removeListener`, `cancel`.
- **R5 — Booleans read as questions.** `isFrameSettled`, `isNavigationActive`, `isOffline`; never `frame_settled` on a foreign surface.
- **R6 — Events are `on<PastParticiple>`.** `onMapReady`, `onCameraChanged`, `onInstruction`, `onSpeechInstruction`, `onDeviationChanged`, `onPhaseChanged`, `onArrival`, `onError`.
- **R7 — Units live in the name.** `_meters`, `_seconds`, `_pixels`, `_degrees`, `_bytes`; `distanceRemainingMeters`, `durationRemainingSeconds`; never `ms`, `px`, `deg` in identifiers.
- **R8 — No vendor in a public name.** `registerMapquestProviders` bakes MapQuest into every call site and contradicts provider genericity; vendor names belong in provider crates and registry descriptors.
- **R9 — No platform/internal leakage.** `Surface`, `Gpu`, `Canvas`, `NativeWindow`, `Pointer`, `Descriptor` never appear in a name a developer types; `MapSurfaceTargetHandle` carries `ANativeWindow*` / `UIView*` and stays internal.
- **R10 — No transport-mode suffixes.** `_live` (`forwardGeocodeLive`, `calculateRouteLive`, `fetchRasterTileLive`) describes the harness transport, not an SDK operation; live/recorded is a provider registration, never a method name.
- **R11 — snake_case inside Rust/UDL only.** UniFFI camelCases UDL members for Kotlin, Swift and RN; wasm-bindgen preserves Rust names unless each export carries `#[wasm_bindgen(js_name = ...)]`, so every wasm export sets `js_name`.
- **R12 — Abbreviations.** `SDK`, `URL`, `HTTP`, `GPS`, `MVT` allowed in prose, never as identifier shorthand; `Gpu` is an implementation word, not an API one.
- **R13 — Values are immutable, verbs live on the owner.** `MapCamera` is a value; change the camera by telling the view (`setCamera`), not by mutating the camera.
- **R14 — Prefix scope by plane, not by vendor.** `Map*` for map-drawn things (`MapView`, `MapCamera`, `MapStyle`, `Marker`, `Polyline`, `Polygon`), `Navigation*` for trip/session data (`NavigationState`, `NavigationListener`, `NavigationPhase`); `MapNavigationController` mixes both.

Never rename: `GeographicCoordinate`, `BoundingBox`, `RouteStep`, `RouteLeg`,
`RouteOptions`, `AvoidOptions`, `NavigationPhase`, `SdkError`, `MapCamera`.

### Create and lifecycle

Kotlin builds `MapView(context, maps)` as a `FrameLayout` and forwards `onStart` /
`onStop` / `onDestroy`; Swift builds `MapView(frame: .zero, maps:)` with no lifecycle
forwarding; React Native constructs `new MapView(maps)` and binds the native host view;
wasm constructs `new MapView(canvas, maps)` and awaits `mapView.ready`. Readiness is
`MapView.OnReadyListener.onMapReady(mapView)` everywhere, and
`configureProviderSet("mapquest", credential)` throws `SdkException` verbatim. The
Android and iOS views hold their callback listener weakly, so a listener that captures the
host that owns the view cannot retain a cycle; the host keeps the listener alive for as
long as it wants callbacks. The failure-phase set is the same nine cases on every native
target: surface, resize, draw, camera, overlay, locationIndicator, baseMap, tap and
listener. The browser canvas has no platform listener to isolate; it reports the
contract's coded errors instead.

### Choosing a provider

`configureProvider(contract, providerKey, credential)` selects the capability slot by
contract, the provider by registry key, and takes whatever credential that provider
issued; `configureProviderSet(providerKey, credential)` fills every capability the named
provider serves from one credential. `platform/providers.json` owns the descriptors
(key, display name, credential label, per-platform availability, attribution, terms,
fixture routes, wasm registration, raster and vector templates, style families);
`Providers.md` lists the keys and capabilities. Nine keys are callable on native and
wasm (`mapquest`, `here`, `google`, `tomtom`, `mapbox`, `radar`, `osrm`, `photon`,
`valhalla`); `openstreetmap`, `osmus` and `openfreemap` are base-map declarations.
Keyless providers answer without a credential. Adding a provider is a provider crate, a
registry descriptor and a dispatch row. `providerRegistrations()` reports the serving
key per capability in a stable order. The wasm seam serves construction:
`MapsSdk.create()` resolves the root (`maps.compiledVersion`),
`new MapView(canvas, maps)` binds the canvas (`mapView.sdkCompiledVersion`), the
optional `TileResolution.Retina` argument pins tile resolution for capture harnesses
(default: the `devicePixelRatioThreshold()` rule), the optional
`recordedTileFixturesAreServed` argument decides whether a raster request may probe the
same-origin `/tiles` fixtures before a registered live source (default enabled for the
dev server and test harness; a page that stages no fixtures disables it), and
`initializeSdk()` is the readiness alias.

### Camera

The camera verbs are `mapView.camera`, `setCamera(camera)`,
`animateCamera(camera, durationMs)`, `fitBounds(bounds, edgeInsets, maximumZoom)`,
`panByScreenPixels(deltaXPixels, deltaYPixels)`, `zoomByLevels(deltaZoomLevels)`,
`rotateByDegrees(clockwiseDegrees)` and `cameraGeographicBounds()`; a gesture cancel
stops an animation. The browser keeps the pan, zoom and rotate algebra on `MapCamera`'s
screen-point members and exposes `rotateByDegrees` beside them on the canvas view. The
Android, iOS, React Native and WebAssembly views expose the same readbacks:
`hasDrawnFirstFrame`, `viewportPixelExtent`, `viewportWidthPixels`,
`viewportHeightPixels` and `displayScale`; the native Android and iOS views also expose
the contract `ViewportSize` record through `viewportSize`. The native views hold the
contract `MapCamera` as their only camera state, and every animation frame is one
`MapCamera.interpolate` call; the wrapper's camera value is a projection of the
readback, not a second store. Camera changes stay a callback (`onCameraChanged` on
Android and React Native, `mapView(_:didChangeCamera:isGestureDriven:)` on iOS).

| Member | Returns | Behavior and failure modes |
| --- | --- | --- |
| `MapView.camera()` | `MapCamera` | The pose the view holds. Starts at latitude 0, longitude 0, zoom 2, north-up and top-down; every `set_camera`, `fit_bounds` or accepted gesture transform updates it. The view stores its own pose so a wrapper reports the same value it hands to `draw`; drawing still receives the pose as an argument. Cannot fail. |
| `MapView.set_camera(camera)` | nothing | Adopts a validated pose and cannot fail. The constructor clamps zoom and pitch and wraps the bearing, so adopting never changes an overlay. |
| `MapView.fit_bounds(bounding_box, edge_insets, maximum_zoom_level)` | `MapCamera?` | Frames the box inside the attached viewport's inset region, top-down and north-up, at the largest zoom keeping the whole box inside the insets and clamped to the maximum; the center anchors on the inset region's center. Answers the adopted camera, or null when no surface viewport is attached (nothing changes). Throws `InvalidCoordinateInput` when the box is not canonical, the insets are negative or leave no inset area, the maximum zoom is not finite, or the box spans no positive world area. A refused fit keeps the previous camera. Uses the attached viewport instead of taking one. |
| `MapView.camera_geographic_bounds()` | `BoundingBox?` | Unprojects the four viewport corners through the current camera. Answers null when no surface viewport is attached or the projection cannot answer. At a steep pitch, when fewer than three corners reach the ground, the camera's own ground scale bounds a box around its center instead. |
| `MapCamera.interpolate(start_camera, target_camera, fraction)` | `MapCamera` | The one camera-interpolation curve. Clamps `fraction` into `[0, 1]` and eases with smoothstep, moves the center along the shortest longitude path in Mercator space, interpolates zoom and pitch linearly and takes the shortest bearing arc. At or below zero it answers `start_camera` verbatim; at or above one, `target_camera` verbatim, so animation endpoints are exact. Throws `InvalidCoordinateInput` when `fraction` is not finite. |

UniFFI generates `camera`, `setCamera`, `fitBounds` and `cameraGeographicBounds` from
the snake_case UDL. The browser maps them onto the canvas view with explicit viewport
and field-of-view arguments, because it has no attached platform surface:
`mapView.camera()` reads the stored pose, `setCamera(camera)` adopts a validated pose
and borrows the camera,
`fitBounds(southWestLatitude, southWestLongitude, northEastLatitude, northEastLongitude, widthPixels, heightPixels, insetTopPixels, insetRightPixels, insetBottomPixels, insetLeftPixels, maximumZoomLevel)`
answers the adopted camera or null before initialization,
`cameraGeographicBounds(widthPixels, heightPixels, fieldOfViewDegrees)` applies the
steep-pitch ground-scale fallback, and static
`MapCamera.interpolate(startCamera, targetCamera, fraction)` keeps exact endpoints and
the shortest bearing arc. `renderFrame(camera, fieldOfViewDegrees)` keeps its per-frame
camera argument, and `MapCamera.groundMetersPerScreenPixel` and the projection methods
also take the viewport explicitly.

### Overlays, gestures and location

`Marker` / `Polyline` / `Polygon` are binding-layer types converting to the existing
`MapOverlayDescriptor` list in one `setOverlays` call; that record stays inside the FFI.
The binding calls are `addMarker`, `addPolyline`, `addPolygon`, `removeOverlay` and
`clearOverlays`.

The id-addressed members are `MapView.add_overlay` / `update_overlay` / `remove_overlay`
(Kotlin `addOverlay` / `updateOverlay` / `removeOverlay`). `add_overlay(overlay)`
answers a generated opaque identifier (`overlay-1`, a monotonic per-view sequence never
reused, even across `clear_overlays` /`set_overlays`); a refused descriptor throws and
adds nothing. `update_overlay(id, overlay)` replaces the addressed overlay in its draw
position; an invalid descriptor throws and keeps the previous one, and an unknown id
throws a typed `SdkError`. `remove_overlay(id)` answers whether the id was present
(unknown is not an error). `clear_overlays()` clears the bulk list and every addressed
overlay; `set_overlays` replaces the drawn list, including addressed overlays, and drops
the bookkeeping. Overlay state, the addressed set and the identifier sequence outlive
attach/detach.

`MapView.set_location_indicator` takes a state and a style, `clear_location_indicator`
removes it, and a null style field resolves to its documented default; validation is
all-or-nothing and the state outlives attach/detach. Gestures switch through
`mapView.gestures.isPanEnabled`, `isZoomEnabled`, `isRotateEnabled` and `isTiltEnabled`,
and `MapView.InteractionListener` reports `onPanBegin`, `onPan` and `onPanEnd`. The
three `MapCamera` gesture members (`pan_by_screen_pixels`,
`zoom_by_levels_around_screen_point`, `rotate_by_degrees_around_screen_point`) carry the
algebra in the contract, so all four shells compute identical results.

### Capability facades: search, routing, navigation

`SearchEngine(maps)` exposes `search(query, boundary)`, `suggest(query)` for type-ahead
and `reverseGeocode(coordinate)`. `RoutingEngine(maps)` exposes
`calculateRoute(waypoints, RouteOptions(...))` and
`calculateDistanceMatrix(origins, destinations, TransportationMode.DRIVING)`.
`Navigator(maps)` exposes `startNavigation(route, NavigationOptions(...))`,
`updateLocation(locationUpdate)`, `applyReroute(replacementRoute)`, `stopNavigation()`
and `addNavigationListener(listener)`, which returns a `Subscription` whose `cancel()`
is idempotent. The UDL members are `Navigator.add_navigation_listener` and
`Navigator.stop_navigation`. The listener has four methods — `onInstruction`,
`onSpeechInstruction`, `onDeviationChanged` and `onPhaseChanged` — and the four topics
stay inside the implementation, so a listener that implements only `onInstruction` still
must not receive speech there.

`stop_navigation()` ends the trip and clears trip state: `current_trip_state` /
`current_instructions` answer null, and later fixes, reroutes and reroute-request
signals are dropped until `start_navigation` begins a new trip. It resets the
speech-trigger band memory and the reroute-recalculation gate with the trip (utterance
ids stay monotonic; the configured reroute policy persists) and leaves listener
subscriptions untouched. No stop event is dispatched: the native reducer and the frozen
phase channel have no stop transition.

Traffic is served by `MapSdk.fetch_traffic_incidents` and `MapSdk.fetch_traffic_flow`,
both taking a `BoundingBox`; the `TrafficEngine` form is the naming target, not a
separate contract interface.

### Offline downloads

`OfflineManager(maps)` exposes `tileCacheTerms()` and
`setTileTimeToLive(timeToLiveSeconds)`; the provider's declared terms ceiling clamps
what the cache stores, and the readback reports the effective value.

| Member | Shape |
|---|---|
| `OfflineManager.region_tile_count(region)` | synchronous count of covered tiles, so a settings surface can warn before a large download |
| `OfflineManager.download_region(region, progress_listener)` | async; returns the final `RegionRecord` |
| `OfflineManager.cancel_region_download(region_id)` | signals an in-flight download; idempotent and a no-op for an unknown or finished region |
| `OfflineManager.region_records()` | async; every region stored on disk |
| `OfflineManager.region_record(region_id)` | async; one region, or `null` when the id is unknown |
| `OfflineManager.delete_region(region_id)` | async; removes the region and returns a `RegionRemovalReport` |

`set_tile_pack_byte_budget(byte_budget)` reserves payload bytes for tile packs beside
the general LRU cache, and `tile_pack_byte_budget()` reads the effective reservation; a
download that would exceed the budget stops, keeps its stored tiles and membership,
reports `CacheOperationFailure`, and resumes later under a raised budget. Ordinary
eviction never frees a present pack tile, and the structural 65,536-tile cap remains the
only tile-count limit.

The records are `RegionDefinition` (region id, display name, bounding box, minimum and
maximum zoom, image format, tile resolution, optional requested retention),
`RegionRecord` (that shape plus effective retention, member and present tile counts and
present payload bytes), `RegionDownloadProgress` (region id, total and completed counts,
network-fetched and disk-served split, `RegionDownloadPhase`), `RegionDownloadPhase`
(`Downloading`, `Completed`, `Cancelled`, `Failed`) and `RegionRemovalReport` (removed
entry count and payload bytes). `RegionDownloadProgressListener` follows
`[Trait, WithForeign]`; `on_region_download_progress` runs on an SDK worker thread and
must marshal to the UI thread. A cancelled download is a successful partial result
(terminal phase `Cancelled`), and a later download resumes from the tiles on disk. A
region deeper than the provider's declared raster ceiling is refused with
`InvalidCoordinateInput`; there is no cancellation token and no new `SdkError` variant.
The WebAssembly surface binds no `TileCacheInstallation`, so its façade does not serve
these members.

Routing from a compiled archive is a contract function on every native surface — archive
bytes in, a `Route` out — sharing one `rustic-maps-core` implementation with the wasm
`offlineRouteFromArchiveBytes` export.
`offlineRouteFromArchiveBytes(archiveBytes, start, end)` uses the archive profile's
default options (automobile, fastest, metric); a corrupt archive throws
`OfflineRoutingFailure`. `OfflineRoutingEngine.fromArchiveBytes` remains the v2 target,
not a requirement.

### Tile and base-map registration

A raster source is declared with `registerUrlTemplateRasterTileSource(source)` or
selected per capability with
`configureProvider(ProviderContract.RasterTiles, "openstreetmap", "")`; a vector base is
installed with `setVectorTileSource(source)`. A raster provider or credential change
reaches the map through `reloadTileSource()`, which re-resolves the provider and drops
pooled tiles without an attach/detach cycle, keeping camera, overlays and the location
layer. The browser serves the same registry through `configureProvider`,
`providerRegistrations`, `configureProviderSet(providerKey, credential)` and
`clearProviderRegistrations`; `registerProvider` / `clearProvider` are gone.

Application code can serve a vector base: implement `VectorTileProvider`
(`sourceDescriptor()` describes the tileset, `fetchVectorTile(tileX, tileY, zoomLevel)`
returns its bytes) and register it with
`registerVectorTileProviderFromForeign(provider)`. The SDK selects it under the key
`application`, named in
`ProviderVectorTileSource(providerKey = "application", styleId = …)`;
`vectorTileProviderIsRegistered()` reports whether the slot is filled. The URL-template
source record carries the tileset's terms text, `{s}` subdomains, per-request headers
and style hints; null or empty fields declare none.

`setProviderVectorTileSource` installs a base from a provider configured for vector
tiles; `setProviderVectorTileSourceFromDocument` fetches that provider's published style
document through its own authenticated client, so the credential stays in the provider
layer and the request keeps its transport, pacing and retry policy. Compiled documents
are cached per provider and address. A failed fetch, decode or compile throws and leaves
the previous base in force. `vectorTileSourceStatus()` reports what the base draws and
what its last resolved frame achieved. The same record crosses every target, and the
browser spells each field in lower camel case: `is_configured` /`isConfigured` (a base
is installed), `style_id` /`styleId`, `source_name` /`sourceName`, `attribution_text`
/`attributionText`, `maximum_zoom_level` /`maximumZoomLevel`, `drawn_tile_count`
/`drawnTileCount`, `failed_tile_count` /`failedTileCount`, `last_failure_detail`
/`lastFailureDetail` (null when none), `unsupported_property_count`
/`unsupportedPropertyCount`, `unsupported_property_names` /`unsupportedPropertyNames`
(distinct, scope-qualified, sorted, at most 32), `degraded_asset_names`
/`degradedAssetNames` (sorted, at most 16) and `source_layer_counts`
/`sourceLayerCounts` (per-source `matched_layer_count` and `drawn_layer_count`, sorted
by source id).

The two name lists are bounded so a large vendor document cannot grow the status without
bound; the count still reports every diagnostic. A document whose declared vector source
names a tileset the provider does not serve is refused at install, naming both, rather
than painting fragments.

### Readiness and errors

`mapView.setOnReadyListener(...)` reports that the map can draw and project.
`maps.diagnostics.addListener(listener, SdkLogSeverity.WARNING)` replaces
`subscribe_to_diagnostic_events`; `flushRecent(listener, severity, maximumCount)`
replays buffered events. `SdkException` carries the typed, verbatim detail; there are no
string-based error callbacks, and readiness is the only callback.

### Ownership split and the frame pump

The shipped SDK wrapper owns surface acquisition and lifetime, the frame pump, resize,
the camera value store and animation, gesture-to-camera deltas, overlay bookkeeping by
id, readiness and error derivation, and pointer-to-coordinate for taps; the platform
application owns widgets, sheets, navigation UI, TTS and the provider credentials UI.

The frame pump lives in the platform wrapper (Kotlin/Swift), never in Rust: the contract
states there is no SDK render loop (`rustic_maps.udl`: "never an SDK-internal loop"),
moving it would need a foreign-callback interface and a UIKit/Choreographer threading
story, and only the wrapper observes window attachment and pause. **Android** uses
`Choreographer.postFrameCallback` + a `Channel<Long>(CONFLATED)` + one consumer
coroutine (the shape at `ReferenceMapController.kt:744-778`), so XML and Compose hosts
share it: post from `onAttachedToWindow`, stop on `onDetachedFromWindow`,
`onWindowVisibilityChanged != VISIBLE` or `setRenderingPaused(true)`. **iOS** uses
`CADisplayLink` on `.main` /`.common`, started in `didMoveToWindow` when
`window != nil`, invalidated when `nil`, plus `setRenderingPaused`.

Per tick the wrapper resizes when the capped pixel extent changed, calls
`frame_settled(camera)` (which throws only when detached, `udl:1468-1477`), draws with
at most one frame in flight (`SdkException.RenderingSurfaceUnavailable` retries next
tick), and pauses the pump when settled, because `draw` fetches inside the call and
`frame_settled == true` means nothing is pending (`Choreographer.removeFrameCallback` /
`displayLink.isPaused = true`).

Resume on camera set/animate, gesture delta, overlay mutation, location-indicator
change, surface created/changed, window attach or visibility,
`setRenderingPaused(false)`, `retryAttach`, and a ~1 s watchdog tick. Drop to a 1 s
retry cadence when `deferred == 0` and `unavailable > 0` persist with an unchanged pose,
or a permanently failing provider becomes a 60 fps spin against the network (the
scheduler retries `Unavailable` tiles every frame:
`rustic-maps-rendering/src/tile_scheduler.rs:11-12, :34-35`). `setRenderingPaused(true)`
in `onStop` /`scenePhase == .background` releases the GPU surface early; `retryAttach()`
follows `onError`.

### Device pixel ratio

The committed styles declare point/CSS sizes while the surface draws device pixels. The
wrapper reports device pixels per point with `MapView.set_device_pixel_ratio` whenever
it applies the drawable scale (attach, resize, rebuilt native view), and the SDK
multiplies placed glyph sizes, overlay line widths and marker/pin radii by that ratio
exactly once, so labels keep their declared point size on a 1×, 2× or 3× surface.
Android reports `resources.displayMetrics.density` (1.0 until the display resolves); iOS
its capped drawable scale (`drawable pixels / point`); the wasm canvas derives its own
from `canvas.width / clientWidth` and carries no setter, so the member stays
native-only.

### Native view construction

**Android: the surface pointer shim ships inside the AAR.** Android exposes no public Kotlin API for
a `Surface` 's `ANativeWindow*`. The crate builds the Android `cdylib`
(`librustic_maps.so`), so a `cfg(target_os = "android")` module with `jni` and `ndk-sys`
exports `Java_com_angoratek_rusticmaps_map_NativeWindowShim_acquireNativeWindow`, and
the AAR's Kotlin object loads it with `System.loadLibrary("rustic_maps")`. A fixed
class/package name makes the mangled symbol a compile-time constant; a consumer ProGuard
keep rule covers obfuscation. Release the window on every failure path: both current
app-side hosts leak one `ANativeWindow*` reference per failed attach.

**iOS: the view owns its own layer pointer.** `MapView: UIView` with `layerClass == CAMetalLayer`
hands Rust `Unmanaged.passUnretained(self).toOpaque()` from inside the view. It must
implement `init?(coder:)` (the current app-side view `fatalError` s, so a Storyboard or
XIB cannot use it); cap the drawable at the platform's texture limit
(`max_texture_dimension_2d` is 2048 on downlevel adapters, so an unguarded full-screen
buffer on a tall phone is rejected); and detach in `dismantleUIView` /
`didMoveToWindow(nil)`, never in `deinit`, so the Rust side releases its surface while
the layer exists.

**React Native: one SDK object, owned by the package.** The generated JSI bindings construct their
own `MapSdk`, and a foreign handle cannot be imported into them. A native `<MapView>`
therefore uses the package's SDK object and proxies calls through its module; otherwise
two registries (and two SQLite tile caches) exist in one process. Navigation needs no
such handle: the generated `Navigator` creates its own native navigation object and
exposes the contract's `NavigationListener` (`onNavigationInstruction`,
`onNavigationPhaseChange` and the other topics). The curated `MapsSdk` proxy keeps its
provider-scoped members (distance matrix, traffic, credentials), which need the shared
provider registry.

### Device positioning

The contract carries one positioning controller. `PositionFix` holds a
`GeographicCoordinate coordinate`, optional `horizontal_accuracy_meters`,
`course_heading_degrees` and `timestamp_seconds`; `PositionSourceError` has four values
(`PermissionDenied`, `ServiceDisabled`, `Unavailable`, `Timeout`); `PositionController`
exposes `feed_fix(fix)` (throwing `SdkError`), `source_failed(error)`, `latest_fix()`,
`smoothed_course_degrees()`, `stale_after_seconds()`, `is_stale(now_seconds)` and
`source_status()`.

The host owns the OS location API and permission prompt and pushes fixes and failures
into the controller, which validates each fix, ignores stationary repeats when averaging
course, smooths the course around the circle, tracks staleness and records source
failures. A controller built before any fix answers `latest_fix` as null; an invalid fix
throws `SdkError::InvalidCoordinateInput` with the validator's detail and leaves the
previous state. The wasm seam exposes the same class (`feedFix`, `sourceFailed`,
`latestFix`, `smoothedCourseDegrees`, `staleAfterSeconds`, `isStale`, `sourceStatus`);
the browser demo's Location settings use it with `navigator.geolocation`.

## 5. The provider layer

### What everymap-rs owns

One abstraction serves both projects: `everymap-rs` keeps its own domain API for
applications that never render a map, and `rustic-maps-sdk` consumes the same crates for
routing, geocoding, search, traffic, raster and vector tiles. The UDL, reference
applications, package identities and provider-name guard are unchanged by the switch.

The SDK pins `everymap-rs` **0.4.7** (`Cargo.lock`), publishing `everymap-core`, eleven
provider crates and a CLI: HERE, Google, TomTom, Mapbox, Radar, MapQuest, Photon, OSRM,
Valhalla, URL-template raster and URL-template vector.

1. `everymap-core` owns the contracts and plumbing: transport seam, pacing, retry, observation, credentials and the domain traits.
2. `everymap-providers-*` owns vendor knowledge: MapQuest, OSRM, Valhalla, the URL-template sources and the OSM US/OpenFreeMap descriptors, beside HERE/Google/TomTom/Mapbox/Radar.
3. `rustic-maps-sdk` depends on them directly: the registry and catalog answer with everymap provider instances, the cache wrappers wrap everymap traits, and the wasm bindings dispatch through the browser transport.
4. The SDK keeps what is renderer- and product-specific: the UDL contract, the offline `RMOG` graph engine, the tile schedulers, the reference applications and the registry descriptors.

Photon and the OpenStreetMap US source live in the provider layer, so one `reqwest`
major and one crate family remain.

### Trait mapping

The SDK contracts map to everymap's as follows. `GeocodingProvider` forward and reverse
map to `Geocoder`, with the result shape widened to the SDK's quality classes and
options mapped. `SearchPlaceProvider` settled search maps to `Geocoder` with a boundary;
`search_autocomplete` maps to the autocomplete trait. `RoutingProvider` maps to
`Router`, requiring ordered waypoints, legs, maneuver/speech/lane, shape and
`route_capabilities`. `DistanceMatrixProvider` and `ElevationProvider` map to their
traits. `TrafficIncidentProvider` and `TrafficFlowProvider` map to `TrafficProvider`,
requiring bounding-box queries, flow geometry and congestion level. `RasterTileProvider`
maps to `TileProvider` with typed format and resolution echoed in the response.
`VectorTileProvider` maps to the vector-tile trait with a source descriptor.
`OfflineRoutingProvider` maps to the offline-routing trait, and the `RMOG` engine stays
here. The registry, cache-then-network and tile cache sit above the traits and wrap
everymap traits unchanged.

### Registry and catalog

The registry is one optional slot per provider contract, so a map may draw raster tiles
from one provider, plan routes with another and search with a third; an uninstalled
capability answers calls with `ProviderNotConfigured`. The ten contracts are
`Geocoding`, `Routing`, `DistanceMatrix`, `PlaceSearch`, `TrafficIncidents`,
`TrafficFlow`, `Elevation`, `RasterTiles`, `VectorTiles` and `OfflineRouting`.

`MapSdk.configure_provider_set(provider_key, credential)` installs every capability a
named provider serves; `MapSdk.configure_provider(contract, provider_key, credential)`
replaces exactly one slot. `MapSdk.provider_registrations()` reports, in a stable order,
which key and display name serve each contract and whether it is registered; an unserved
capability carries an empty key and name and `registered` false.

`rustic-maps-providers` carries the one catalog table; the native catalog and the
browser dispatch both read it, their tests compare rows against it, and the registry
test compares `platform/providers.json` against it. The table carries no vendor URL,
credential value or transport. Adding a provider is one row there, one construction
function in the binding's shared seam, a provider crate and a registry descriptor.

### The bridge

`rustic-maps-core` depends on everymap provider instances through the bridge in
`crates/rustic-maps-core/src/everymap_bridge.rs`. The adapters convert records and
errors only; they hold no vendor knowledge and name no provider. The registry, cache
wrappers and UDL provider callbacks speak the SDK's own contracts, with the bridge
converting at the seam; a host provider supplied over the UDL keeps its own
foreign-trait seam. The UDL has nine `register_*_from_foreign` methods: geocoding,
raster tile, vector tile, routing, distance matrix, search place, traffic incident,
traffic flow and elevation. The record adapters such as `EveryMapGeocoder` stay free
conversion functions. A duplicate-abstraction gate fails a new `*Provider` trait outside
the UDL seam, and the provider-name guard keeps vendor knowledge in the crates and
descriptors.

### Provider-layer facts and caveats

- The build registers all nine callable keys on native and wasm; the two URL-template crates remain base-map sources.
- `everymap-core` reads `web-time::Instant`; `std::time::Instant::now()` panics on `wasm32`, trapping every browser provider path.
- `TrafficFlow.speed` declares no unit in the provider layer while the SDK field is kilometres per hour. The only shipped provider reports no speeds, so no wrong value is published; a second traffic provider must report kilometres per hour until the upstream field gains a unit.
- The MapQuest port closed five parity gaps: pacing and retry configuration (`set_rate_limiter`, `set_retry_policy`, `set_request_timeout`, `set_observer`), the imperial unit choice (`RouteOptions::unit_system`), the nine geocoding quality levels (`SearchQuality`), a settled place-search trait (`PlaceSearchProvider`) beside `Geocoder` and `AutocompleteProvider`, and incident coordinates on the core traffic record.
- The process-wide request observer (`install_global_request_observer`) lets the typed `ProviderRequestTrace` keep its facts without each provider crate changing; `TokenBucket::with_maximum_wait` restores the refusal after a ceiling, reported as `RateLimited`.

Upstream crates align their `reqwest` and `thiserror` versions so one binary carries one
of each. The UDL stays addition-only, the registry answers one provider per capability
with independent slots, and the provider layer never names this SDK. Whether the
published layer keeps its trait names, and whether the SDK publishes its cache wrappers
upstream, remain open.

## 6. Offline routing

The offline routing graph is the road network the SDK routes over without a network
connection. `rustic-maps-offline-graph-compiler` compiles one OpenStreetMap extract into
a single `RMOG` archive; `rustic-maps-offline-graph-archive` reads it back with full
validation on every target, and `rustic-maps-core` answers offline routes over it with
A\*. The compiler never ships and stays native-only because its OpenStreetMap PBF reader
does not build for wasm; the format lives in the wasm-viable archive crate, which the
compiler re-exports under its own `archive` path.

### Inputs and output

The compiler reads one OpenStreetMap `.osm.pbf` extract containing the nodes, ways and
turn-restriction relations of the region to route in; anything outside it does not exist
for the graph.

```console
rustic-maps-offline-graph-compiler region.osm.pbf region.rmog
```

After writing, the tool re-reads the file through the validating reader and prints node,
edge, turn-restriction and lane-guidance counts
(`crates/rustic-maps-offline-graph-compiler/src/main.rs:41`). A compile the reader
rejects exits with a failure instead of leaving an unusable archive.

### Container layout

An archive is one little-endian file. Format version 1 opens with a fixed header, then a
table of contents naming every resource, then the payloads in canonical order:

```text
offset  0   magic "RMOG"                                4 bytes
offset  4   format version                              4 bytes
offset  8   table-of-contents entry count               4 bytes
offset 12   table of contents, 48 bytes per entry:
              resource name                            32 ASCII bytes, NUL-padded
              resource offset                          u64, a multiple of 8
              resource byte length                     u64
            resource payloads start on 8-byte boundaries and are separated
            by up to 7 zero bytes; the file length is padded to the same
            8-byte alignment
```

The constants in `crates/rustic-maps-offline-graph-archive/src/archive.rs` are
`ARCHIVE_MAGIC` (`"RMOG"`), `ARCHIVE_FORMAT_VERSION` (`1`), `RESOURCE_NAME_BYTES`
(`32`), `ARCHIVE_RESOURCE_ALIGNMENT` (`8`), `FILE_HEADER_BYTES` (`12`) and
`TABLE_OF_CONTENTS_ENTRY_BYTES` (`48`); the reader requires the names in canonical
order.

| Resource | Record width | Payload |
|---|---|---|
| `nodes` | 8 | quantized coordinate records |
| `edges` | 20 | directed edges |
| `lane_guidances` | 8 | lane guidance records |
| `instruction_strings` | blob | concatenated UTF-8 instruction text |
| `instruction_lookup_indices` | 4 | byte offsets into `instruction_strings`, one per turn restriction |
| `turn_restrictions` | 16 | restricted turns |

The list is `CANONICAL_RESOURCE_NAMES`; the fixed `RESOURCE_COUNT` means a new resource
needs a format version bump, and readers stay strict.

A node record stores latitude and longitude as fixed-point `u32` values at 1e-7 degree
resolution, offset by 90 and 180 degrees (`COORDINATE_QUANTUM_PER_DEGREE`,
`LATITUDE_OFFSET_DEGREES`, `LONGITUDE_OFFSET_DEGREES`,
`NodeRecord::from_geographic_degrees`). An edge record stores the source and target node
index, distance in meters, duration in milliseconds and one packed `encoded_value`
column:

```text
bits  0..3    road class (0 motorway, 1 trunk, 2 primary, 3 secondary,
              4 tertiary, 5 unclassified, 6 residential, 7 service)
bits  3..8    speed in 5 km/h cells (SPEED_QUANTUM_KILOMETERS_PER_HOUR)
bit   8       forward access (along the OpenStreetMap way node order)
bit   9       backward access (against that order)
bits 10..32   reserved, must be zero
```

The bit offsets are named constants from `ROAD_CLASS_BIT_OFFSET` through
`ACCESS_BACKWARD_BIT_OFFSET`, and `SPEED_CELL_LIMIT` caps the speed column at 155 km/h.
`instruction_strings` holds one phrase per recorded turn restriction, in restriction
order; `instruction_lookup_indices` holds one entry per restriction, a byte offset into
that blob or `INSTRUCTION_ABSENT_INDEX` (`u32::MAX`) when no text exists;
`instruction_text` resolves an entry to the text between its offset and the next
non-absent offset. Lane guidance records carry an edge index and a lane count; the slot
exists, but the compiler emits no records.

`flatdata` was rejected because its `build.rs` calls `flatdata::generate`, which shells
out to `python3` and `pip`; `ARCHIVE_FORMAT_VERSION` is the migration seam.

### Compile pipeline

1. **Collect.** One sequential PBF pass records node positions, drivable ways (OSM id, ordered node references, tags) and turn-restriction candidates (`crates/rustic-maps-offline-graph-compiler/src/compiler.rs`).
2. **Profile.** `profile.rs` decides which ways become edges. `highway` selects road class and default speed; drivable values are `motorway`, `trunk`, `primary`, `secondary`, `tertiary`, `unclassified`, `residential` and `service`, while `living_street` borrows residential and every `*_link` inherits its parent class. A plain integer `maxspeed` between 5 and 155 km/h overrides the class default; richer values fall back. `access=no` and `access=private` drop the way. `oneway=yes`, `1` and `true` keep only the node-order direction, `-1` and `reverse` only the reverse, and any other value keeps both.
3. **Build topology.** Only nodes referenced by a surviving way enter, in ascending OpenStreetMap node id order; each segment emits one directed edge per allowed direction. Distance is the haversine distance between the two quantized records, and duration divides it by the stored quantized speed, so the archive re-derives its durations exactly.
4. **Resolve turn restrictions.** A `type=restriction` relation with a `from` way, a `via` node and a `to` way maps onto `no_left_turn`, `no_right_turn`, `no_u_turn`, `no_straight_on` or `only_straight_on`; unresolved candidates are skipped, not fatal.
5. **Encode.** The builder validates every cross-reference and writes the bytes (`encode_deterministic`).

### Lane guidance, determinism and fixtures

The compiler emits no lane guidance records deliberately. OpenStreetMap `turn:lanes`
tags describe which maneuvers each lane permits (`through|through|right`), while
`LaneGuidanceRecord` stores a lane count per edge; a counts-only record cannot represent
the maneuvers or a recommended lane. The resource keeps its slot for a future
lane-geometry extension.

Two compiles of one extract are byte-identical: surviving nodes keep ascending node id
order; edges sort by (source node index, target node index, originating way id);
restrictions sort by (from edge index, via node index, to edge index), with instruction
strings in that order; resources are written in canonical order with every alignment gap
zeroed.

Two fixtures sit beside the compiler, guarded by always-on tests:

- `crates/rustic-maps-offline-graph-compiler/fixtures/osm/routing_grid.osm.pbf` is the routing-grid extract in which three ways survive, one way is dropped by `access=private`, one restriction applies, and eight nodes become six; its test compares committed bytes with the canonical generator's output.
- `crates/rustic-maps-offline-graph-compiler/fixtures/rmog/routing_grid.rmog` is that extract compiled once by the compiler binary; its test regenerates it in process, compares bytes, and re-validates through `from_bytes`, the same loader the browser uses.

Set `MAP_OFFLINE_GRAPH_COMPILER_REGENERATE_FIXTURE` or
`MAP_OFFLINE_GRAPH_COMPILER_REGENERATE_ARCHIVE_FIXTURE` to rewrite a fixture from the
canonical source; both switches live in `tests/common/mod.rs`. The round-trip test pins
node order and coordinates, edge endpoints and canonical order, one-way direction, road
classes, speeds, durations, the restriction record and the instruction string with its
lookup index; a separate test proves two compiles agree byte for byte.

### Reading and validation

`OfflineRoutingNetworkGraph::from_bytes` parses and fully validates an archive before
returning it; corruption never reaches the routing engine. Every failure is one of three
typed reasons, carried by `SDKError::OfflineRoutingFailure` and defined in
`crates/geospatial-types/src/error.rs`:

| Reason | Raised when |
|---|---|
| `ArchiveMalformed` | the input is shorter than the header, the magic is wrong, the entry count is not the canonical six, a name is wrong or out of order, an offset is misaligned or below the previous resource's end, a span exceeds the file, a payload length is not a whole number of records, packed enum values are unknown, reserved bits are set, or the instruction blob is not UTF-8 |
| `VersionUnsupported` | the magic matches but the format version is not this crate's |
| `IndexOutOfRange` | an edge, restriction or lane-guidance record references a node or edge outside the archive, a lookup offset lands past the blob or off a UTF-8 character boundary, or the lookup count differs from the restriction count |

### Native memory-mapped path

On native targets, `MemoryMappedArchive::open` maps the file and validates the
file-level alignment invariants: the region covers at least the 12-byte header, its
length is a multiple of `ARCHIVE_RESOURCE_ALIGNMENT` (the writer pads to that boundary),
and the mapped base address honors the same alignment, keeping table-of-contents `u64`
reads naturally aligned. The bytes then go through the same `from_bytes` validation, so
both paths answer identical routes. Missing, unreadable or unmappable files surface as
`ArchiveMalformed`; the vocabulary has no I/O cause.
`offline_routing_network_graph_from_mapped_file` combines mapping and validation.

### Wasm path

The browser has no `mmap`, so wasm loads from in-memory bytes only.
`OfflineGraphSource::Memory` takes the archive as a byte vector and is the only source
on wasm; an `OfflineGraphSource::FilePath` load is rejected with a typed
`ProviderRequestRejected` message naming the memory source
(`crates/rustic-maps-core/src/offline_routing.rs`). The committed compiled fixture
serves same-origin from the playground dev server, and the wasm bindings expose
`offlineRouteFromArchiveBytes` (archive bytes plus start and end coordinates), which
validates through the same reader and answers a route. It is the browser half of the
contract's `offline_route_from_archive_bytes` free helper; both surfaces delegate to the
same `rustic-maps-core` implementation, so native and wasm answers cannot drift.

### Routing consumer

`ArchiveOfflineRoutingProvider` in `rustic-maps-core` implements the
`OfflineRoutingProvider` trait:

- **Load.** Accepts a file path (native, memory-mapped) or bytes, validates the archive, and builds a half-edge adjacency plus turn-restriction rules once; a failed load leaves any previous graph in place.
- **Snap.** Snaps each request point to the nearest graph node within `NODE_SNAP_TOLERANCE_METERS` (50 m) and rejects coordinates beyond it.
- **Search.** A\* with a haversine heuristic admissible for both weights: straight-line distance for `Shortest`, and that distance divided by the fastest storable edge speed for `Fastest`. `dijkstra_reference_search` is the same search with a zero heuristic, a benchmark baseline only.
- **Restrictions.** Evaluated against the settled path's incoming edge, exact unless a node can be reached on several best-cost paths through differently restricted incoming edges, in which case it over-restricts rather than understating.
- **Maneuvers.** A junction whose signed bearing change leaves the straight band opens a turn step, with `STRAIGHT_ON_BAND_DEGREES`, `SLIGHT_TURN_BAND_DEGREES`, `STANDARD_TURN_BAND_DEGREES` and `SHARP_TURN_BAND_DEGREES` classifying slight, standard, sharp and U-turn maneuvers; a road-class or speed change without a turn opens a `Continue` step. The archive carries no street names, so step texts stay name-free (`"Turn right"`, `"U-turn"`) and are end-anchored on the banner while the maneuver type anchors at the step's opening junction.

`OfflineFallbackRoutingProvider` wraps an online provider: a successful answer passes
through untouched, and an online failure for a request with at least two waypoints is
calculated offline per consecutive pair, with legs joined, distance and duration summed
and bounding boxes unioned.
